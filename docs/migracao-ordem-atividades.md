# Migração da ordem das atividades

O schema de `Atividade` exige uma ordem positiva e única dentro de cada turma. Antes de iniciar a versão que contém esse índice, faça backup do banco e pare temporariamente as gravações de atividades. A migração não remove atividades nem progressos.

Execute primeiro `node scripts/migrarOrdemAtividades.js` para uma prévia somente de leitura. Ela lista as ordens que seriam atribuídas/ajustadas e os índices `{ turma: 1, ordem: 1 }` existentes; se houver índice incompatível, mostra o bloqueio junto com o plano e não grava nada. O planejador preserva as ordens positivas únicas existentes. Para duplicidades, mantém a ordem no documento mais antigo (`createdAt`, com desempate por `_id`) e atribui ordens maiores às demais; registros sem ordem ou com valores inválidos também recebem ordens depois do maior valor válido. A atribuição é separada por turma e determinística, portanto a prévia pode ser revisada antes de aplicar.

Somente após revisar a prévia, manter as gravações suspensas e confirmar o backup, execute `node scripts/migrarOrdemAtividades.js --apply`. O script confere os índices existentes antes de alterar documentos e interrompe sem alterações se encontrar um índice com o mesmo padrão que não seja único, oculto, esparso, em preparação ou use filtro parcial. As atualizações alteram apenas o campo `ordem` de documentos em `atividades`; não removem nem alteram atividades ou progressos, e usam o valor anterior no filtro para detectar mudanças concorrentes. Após atualizar, o script relê todas as atividades e valida que cada uma tem turma e uma ordem positiva única por turma. Só então cria o índice único `{ turma: 1, ordem: 1 }`. Se uma etapa falhar, nenhum documento é excluído; a prévia pode ser executada novamente. Não execute `--apply` em produção sem aprovação operacional e confirmação do backup.

Após o sucesso, implante/inicie a API atualizada. O índice do schema passará a ser criado automaticamente na inicialização, já com os dados reconciliados.
